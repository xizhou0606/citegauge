# 企业工作台与平台管理

平台管理员登录后打开 **工作台 → 平台管理 · 项目接入**。客户账号登录同一工作台，只能访问所属企业的监测项、回答证据、官网分析、采集密钥和流量。每个账号归属一家企业，一家企业可开通多个账号。原有账号、监测数据、SDK 密钥和调度均归自营工作区。

项目按企业和官网域名去重。「未签发密钥」表示已建立网站记录，「等待首次上报」表示已生成密钥。「已收到上报」表示至少有一批通过校验的 SDK 事件，最近上报显示服务器收件时间。这个状态保留历史，即使网站已停止上报。

## 开通企业

1. 在项目接入页展开「开通企业账号」，选择一个空闲数据库，填写企业名称和账号。创建后保存仅显示一次的随机密码，通过你与该客户约定的私密渠道交付。
2. 客户登录后添加监测网站。需要 SDK 的项目从「网站流量」领取该站密钥。已发布的 npm 包直接使用此密钥，无需更改上报地址。
3. 为同一家企业增加账号时选择已有企业。撤销企业成员访问时，从主 D1 的 tenant_members 删除该用户的关联，下一次业务请求即重新校验。客户企业目前不共用自营工作区的报告推送渠道。

## 增加独立 D1

每家客户使用一个独立业务 D1。主绑定 DB 保存 Better Auth、成员归属和原有自营数据。下面以 org02 为例。

1. 运行 `npx wrangler d1 create citegauge-tenant-org02`。
2. 在 wrangler.jsonc 的 d1_databases 数组增加绑定 TENANT_ORG02，填入实际数据库名、创建时返回的 database_id，以及 migrations_dir 值 migrations/d1。绑定后缀使用大写字母和数字，以字母开头，最多 24 位。一个数据库只能属于一家企业，已分配的绑定和数据库标识需长期保留。
3. 运行 `npx wrangler d1 migrations apply TENANT_ORG02 --remote`，发布含新绑定的 Worker。后台会列出可分配的 org02。
4. 后续迁移必须应用到主库及所有企业绑定，再发布依赖新表的代码。可用 `npm run db:migrate:all -- --remote` 逐库执行，失败时修复并重跑。

DO 根据实例身份选择所属企业的 D1。采集端根据密钥后缀路由，并在目标库校验完整密钥哈希及网站域名。企业库内的归属标记用于核对绑定，不匹配时拒绝读写。
