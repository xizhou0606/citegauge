# 指标与覆盖范围

页面访问可切换今天、近 7 天、近 30 天，按北京时间的自然日统计。今天按小时展示，其余按日展示。人均浏览次数为期间 PV 除以去重 UV；浏览频次按同一访客在期间内的 PV 分为 1 次、2–4 次、5 次及以上。爬虫与文件请求使用近 30 天窗口。首次上报前使用「—」，成功上报后显示已观测到的次数。

| 指标 | 统计方式 |
| --- | --- |
| PV | 到达 Node 服务的 GET 页面请求，响应类型为 HTML 且状态为 2xx。跳过常见机器人、预取请求及非文档资源。 |
| 估算 UV | 对同一网站的匿名访客标识在整个窗口内去重。默认在站点本地对连接 IP 与 User-Agent 作带密钥的哈希，原始 IP 不进入上报。 |
| AI 爬虫 | 按请求的 User-Agent 匹配 GPTBot、OAI-SearchBot、ClaudeBot、Claude-SearchBot、PerplexityBot 和 Bytespider。名称由请求方声明。 |
| XML / TXT | 统计到达服务的 .xml、.xml.gz、.txt 请求，保留路径和最终响应状态，包含 304 和 404。查询参数会被去掉。 |

共享出口或反向代理可能让多个浏览器合并为一个访客，网络变化可能让同一访客重复计数。已经有匿名访客标识的网站可通过 [visitorId](./api.md) 提高去重质量。轮换采集密钥会改变后续生成的访客哈希。

## 浏览器页面访问

首次加载、恢复浏览器缓存页面和站内路径切换各计一次 PV。重复初始化、仅修改查询参数或锚点不会增加 PV。UV 按该网站本地存储的随机标识去重，禁用存储时仅在当前页面生命周期内去重。浏览器事件只传送随机事件 ID 和访客 ID。设备分布按浏览器声明推断电脑、手机或平板，仅保存分类。无法判断的请求显示「未识别」，采集分类前的访问归入「历史未记录」。服务端验证已启用的站点域名，并将浏览器指标和服务端请求分别统计。

## 部署方式

Express、Fastify 的 Node HTTP/1 服务，以及基于同一模块的服务端框架可以直接采集。纯前端路由切换、浏览器缓存、CDN 缓存命中和纯静态托管会绕过这个入口。Workers 等仅提供 Fetch 事件的运行时和原生 HTTP/2 服务需要单独的接入方式。

若同时导入 CDN 日志和 SDK 记录，应选取互不重叠的时间段；不同层的请求标识和时间可能不同。爬虫访问仅说明抓取请求到达了站点。回答里的官网引用率在「回答与引用」单独计算。
