# 引迹 CiteGauge · MVP 设计与验收对照

2026-11-12，本地桌面项目。项目内此前未发现独立的设计文档，此处依据聊天中的竞品分析、架构选型、三个阶段的交付目标，以及随后明确的 Cloudflare、GitHub 开源和自身 GEO 要求。回归检查针对本地实现；仓库和线上环境需分别发布、验收。

## 需求对照

| 原设计交付目标 | 当前实现与适用范围 | 仍需补齐的验收 |
|---|---|---|
| 题库、品牌、别名、竞品与重复采样 | 每个监测项固定一个问题、品牌和渠道，支持多次取样。网页和 API 独立统计。 | 跨渠道批量运行同一题集、问题版本与品牌题/非品牌题分组。核对 2 渠道 × 3 次生成 6 个独立结果。 |
| 豆包、DeepSeek 消费者网页自动取样 | 两个网页渠道已支持人工导入，正文、来源核对状态、页面链接和可选 PNG/JPEG 原始截图绑定同一样本。 | 两个网页端的自动提问、回答完成判定和引用提取。使用授权账号，同题重复采样，人工复核截图和原文，统计失败率、单份有效样本成本。 |
| 火山方舟与 DeepSeek 官方 API | 各自有适配器；按需及每日调度已实现。方舟解析答案引用标注，DeepSeek 文本渠道标记来源不可观测。 | 真实账号调用、实际返回的引用字段和成本有待验证。本次使用固定响应用例。 |
| 提及、推荐、官网引用、竞品与证据 | 30 个 UTC 自然日内按问题、渠道统计；分子可点击回看，竞品和前 20 个引用页面也能下钻。推荐由人工复核，支持摘录和明确名次；旧样本默认为未复核。 | 推荐判定一致性需用真实回答验证。来源中心仍缺跨题域名聚合、权属分类及内容变更前后的对比。 |
| 证据历史、解析版本、复算 | 原始响应、人工导入记录和解析器版本已保存。复核不会修改原始记录，截图下载要求鉴权。 | 缺少按解析器版本批量回放与新旧结果差异核对。已有人工样本的历史截图无法事后补造。 |
| 采样队列、失败恢复、预算 | Cloudflare Durable Object alarm 承担每日调度；同一任务编号去重，失败样本单列。手动 API 请求仍同步等待。 | 异步任务状态、可重试错误分类、前端重发复用任务编号、渠道限额、单位有效样本成本。验收时模拟超时、重复投递和限额耗尽。 |
| 项目与租户隔离 | 当前是单团队自托管，管理员通过 Better Auth 账号和密码登录。 | 代理商共享 SaaS 还需租户、项目成员权限、配额及跨租户读写隔离测试。 |
| 趋势与客户周报 | 单监测项趋势、竞品对比、引用 URL 与原文下钻已可用。 | 跨问题的周报仍缺本周相对上周的新增/消失提及与引用、可分享报告及对应证据。 |
| Cloudflare 部署与 GitHub 开源 | 已有 MIT 仓库、CI、Worker 入口和 PostgreSQL 迁移。Cloudflare 是后续明确要求，替代了初案的 ECS、RDS 和 OSS。 | 此次修改仅在本地验证，生产认领状态、正式域名和这次改动上线后须分别核验。 |
| 产品自身的 GEO | 首页、方法、渠道、关于项目均返回 HTML；包含 canonical、结构化数据、sitemap、robots 和 llms.txt。工作台有自身监测入口。 | 验证正式域名对爬虫的可访问性；在非品牌题与品牌题上分别建立真实样本基线并持续复测。 |

## 本轮验收记录

- 构造其他项目 220 条更新样本，确认当前项目较早的记录仍计入。覆盖时间边界、相同时间戳分页、失败与未知状态、同一回答重复引用去重。
- 为看板、趋势和下钻使用统一时间窗与分母。当前问题、渠道内读取全部有效回答，历史每页 25 条。
- 人工明确推荐计入已复核分母，正向判断必须有原文摘录。支持撤销复核，继续保留原始证据。来源元数据不完整的多段 API 回答记为不可观测。
- 用独立本地数据库在浏览器中走通创建监测项、录入网页样本与截图、筛选提及及竞品、按引用 URL 查看证据、保存推荐复核。验证截图下载字节与上传一致、无密钥读取被拒、虚构摘录被拒。

## 下一次试点顺序

1. 在一个国内消费者入口跑通真实网页采样。交付可复核的原文、截图、引用和采样耗时，再用同一题集接第二个入口。
2. 将采样做成持久化的异步任务，用失败率、人工维护时间及真实账单计算每份有效样本成本。
3. 用一个试点品牌的固定问题连续运行两周，交付带来源证据的周度变化报告。对外提供共享 SaaS 之前单独验收租户隔离。
